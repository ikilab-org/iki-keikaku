## 2. 出典の選び方

**残りやすいものを優先する。**

| 残存性 | 資料 |
|---|---|
| 高い | 議案書PDF、議会会議録、決算審査意見書、施政方針、計画本体PDF、条例・規則 |
| 中 | 計画の紹介ページ、統計データ集、パブリックコメント実施**予定**一覧 |
| 低い | 入札公告、委員募集、**実施中**のパブリックコメント、イベント告知、年度限定のお知らせ |

残存性が「低い」ページを**唯一の根拠にしない**。必ず「高い」資料で相互確認するか、下記の保存を行う。

### 所管課は例規集で確認する

計画の掲載ページにある「このページに関するお問い合わせ」は、**所管課の根拠としては弱い**。組織改編があっても
更新されないことがあり、計画本文の課名は策定時点のもので固定されるためです。

**[例規集](https://www.city.iki.nagasaki.jp/section/reiki/reiki_menu.html)の行政組織規則（部・課の設置と分掌事務）を一次資料にしてください。** 改正のたびに
更新され、施行日が明記され、告知ページと違って消えません。2026-08-12 に取り直したところ、次が判明しました。

- **長寿支援課**（令和7年6月1日施行の規則で保健環境部に所在）が、資料集のどこにも登場していなかった
- 「高齢者福祉計画・介護保険事業計画」は**1冊で2課にまたがる**。規則の分掌は「介護保険事業計画に関すること」＝保険課
  介護保険班、「高齢者福祉に関すること」＝長寿支援課 長寿福祉班。根拠法が老人福祉法20条の8と介護保険法117条の
  2本立てであることに対応する
- **政策企画課・いきいろ子ども未来課は現存しない。** 政策企画課の移管先は計画ごとに異なり、一括置換では直せなかった

**根拠法が複数ある計画は、所管も複数である可能性を疑ってください。** 一体策定が多い自治体では、
1冊の計画書に対して所管課が1つとは限りません。

なお、この改編を告知したページは調査時点ですでに404でした（上の表）。**組織改編の告知は残存性が「低い」、
例規集は「高い」**という関係にあります。

## 3. 記録すること

すべての出典について、次を `sources/MANIFEST.md` に記録します。

- 出典名（正式名称）
- URL
- 最終確認日
- 残存性の区分（高/中/低）
- 保存の有無と保存先
- 参照箇所（PDFのページ番号など）

## 4. 保存の方法と、著作権上の判断

**重要**: 壱岐市のサイトには、著作権・免責事項のページはあるものの、
**二次利用の可否やクリエイティブ・コモンズ／政府標準利用規約への言及がありません**
（[著作権・免責事項](https://www.city.iki.nagasaki.jp/3313.html)）。
したがって「出典を書けば自由に転載してよい」とは言えません。

このため、保存は次の3段階で行い、**原則として原本の再公開はしません**。

| 段階 | 内容 | 公開 |
|---|---|---|
| A. メタデータ | URL・取得日・SHA-256・ファイルサイズ・タイトル | 公開する（`MANIFEST.md`） |
| B. 抜粋 | 引用の要件（主従関係・明瞭区別・必然性・出典明示）を満たす範囲の引用 | 公開する（各ページ本文） |
| C. 原本 | PDF・HTMLの完全な複製 | **公開しない**。ローカルまたは非公開の保管場所に置く |

**数値そのものは著作物ではありません。** 計画書の統計表から数値を読み取り、自分で表を作り直して掲載することは、
著作権の問題になりません（表の選択・配列に創作性がある場合は編集著作物として保護されうるので、
そのまま複製するのではなく、必要な数値を抜き出して再構成する）。

**第三者アーカイブへの登録**を併用します。自分で再公開する代わりに、
国立国会図書館のインターネット資料収集保存事業（WARP）や、その他のウェブアーカイブサービスに
URLを登録しておくと、後から誰でも参照できます。実際、第7期計画は WARP に保存されていました。

**恒久的な解決策**として、壱岐市に対して次を提案する価値があります。

> 市の公表資料について、政府標準利用規約（第2.0版）またはクリエイティブ・コモンズ表示（CC BY）に準拠した
> 二次利用ルールを整備し、サイトポリシーに明記していただけないか。

国のオープンデータ基本指針は政府標準利用規約2.0（CC BY 4.0互換）を推奨しており、
これが整備されれば、市民・事業者・研究者・他自治体が市の資料を安心して活用できるようになります。

## 5. 自動チェック

```bash
node tools/linkcheck.mjs                 # 全出典URLの死活確認
node tools/linkcheck.mjs --fail-on-dead  # 失効があれば exit 1（CI用）
```

`.github/workflows/linkcheck.yml` が週次で実行し、失効を検知すると Issue を立てます。

### 誤検知の扱い

自動チェックの 404 は、**必ずしもページが消えたことを意味しません。** 次の可能性があります。

- サーバが HEAD リクエストや bot の User-Agent を拒否している
- WAF がアクセス元を遮断している
- 一時的な障害

**Issue が立ったら、まずブラウザで手動確認してください。** ブラウザで開けるなら誤検知なので、
`data/plans.yml` の該当エントリに `note:` でその旨を記録し、Issue を閉じます。
本当に消えている場合のみ、下記の手順に進みます。

### 200 を返すのに中身がない

**カテゴリの移設では、旧URLが 404 にならないことがあります。** 長崎県サイトでは
`/bunrui/hukushi-hoken/kenkodukuri/` 配下が `kekodukuri/kekodukuri/` へ移った際、旧カテゴリURLが
**200 を返しながら中身が空**の状態で残りました（2026-08-11）。ステータスコードだけを見ると素通りします。

`linkcheck.mjs` は HTML の本文を取得して `<title>` の有無を見ることで、この型も失効として扱います。
手で確認するときは、**ページが開けたかどうかではなく、探している記事がそこにあるか**まで見てください。

移設先の探し方: 記事IDは移設後も引き継がれることが多い。上の例では
`.../kenkonagasaki21/661413.html` が `/doc/page-661413.html` になり、**番号 661413 は同じ**でした。
上位カテゴリの一覧ページから辿るのが確実です。

## 6. 失効したときの手順

1. ブラウザで手動確認する（誤検知の切り分け）
2. 同じ内容が残っている場所を探す
   - 議案書PDF、会議録、施政方針、上位ページの一覧
   - 市の別カテゴリ（組織別ページ／分野別ページで同じ記事が二重掲載されていることがある）
3. 見つかったら `data/plans.yml` の URL を差し替え、`sources` に旧URLと失効日を `note:` で残す
4. 見つからなければ、出典名・取得日・保存済み資料の有無を明記したうえで、
   本文に「※当該ページは掲載終了。◯年◯月◯日取得時点の内容による」と注記する
5. `CHANGELOG.md` に記録する

**検索エンジンのキャッシュを唯一の根拠にしない。** キャッシュも消えます。
