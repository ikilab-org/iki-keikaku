# docs/

分析報告書、市への照会内容、パブリックコメントの提出内容など、
HTMLページの背景になる文書を Markdown で置く場所です。

## 想定する置き方

```
docs/
├── design/
│   ├── 2026-08-12-zenkeikaku-bunrui.md        設計文書
│   └── 2026-08-12-zenkeikaku-bunrui-plan.md   実装計画
├── kaigo/
│   ├── analysis-8th-9th.md          調査・分析報告書
│   ├── city-confirmation-checklist.md   市に確認すべき事項
│   └── 10th-progress-management-draft.md  第10期「計画の進行管理」章 文案
├── koutsuu/
│   └── 2026-08-25-kaiji-seikyu.md   開示請求の記録
└── pubcom/
    └── 2026-12-kaigo-10th.md        提出したパブリックコメント
```

## 設計文書・実装計画（`docs/design/`）

`data/plans.yml` のスキーマ変更やツールの新設など、**リポジトリの構造そのものに手を入れる作業**の
設計文書と実装計画を置く場所です。ページの内容についての分析報告書（`kaigo/` など）とは性格が違うため、
別ディレクトリに分けています。

ファイル名は `YYYY-MM-DD-作業名.md`（設計）と `YYYY-MM-DD-作業名-plan.md`（実装計画）で揃えます。

## 開示請求の記録

情報公開条例に基づく開示請求は、`<分野>/YYYY-MM-DD-kaiji-seikyu.md` に記録します。
**何を請求し、何が出て、何が出なかったか**を残すためのもので、次の3つが揃っていると
後から効きます。

- 請求した文書の一覧（実施要領や様式の番号まで特定した形）
- 決定の内容と、非公開部分に付された根拠条項
- 非公開に対して用意した反論（条例・規則・市の解釈運用基準の該当箇所）

**請求書そのものは置かないでください。**請求者の住所・電話番号を含み、`docs/` は
GitHub 上で誰でも読めます。記録に残すのは請求の中身と結果だけにします。

## 公開の判断

`docs/` に置いたものは GitHub 上で誰でも読めます。次を確認してから置いてください。

- 個別の法人・事業所への評価と読める記述になっていないか（[`../DISCLAIMER.md`](../DISCLAIMER.md)）
- 市への照会前の推測が、事実として読まれる書き方になっていないか
- 出典に取得日が入っているか（[`../sources/POLICY.md`](../sources/POLICY.md)）

市への照会結果が返る前の段階の資料は、「照会中」であることを冒頭に明記してください。

## パブリックコメントの記録

意見を提出したら、提出日・提出先・提出内容をここに残します。
市が公表する「実施結果」（提出意見と市の考え方）が出たら、そのURLも追記します。
これがあると、次期計画のときに「前回何を言って、どう扱われたか」を確認できます。
